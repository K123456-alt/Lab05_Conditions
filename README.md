## Главные выводы
**Условные конструкции** — основа логики программы. Операторы if/else, switch/case и тернарный оператор позволяют программе принимать решения в зависимости от входных данных.

**Безопасность важнее краткости**. Использование int.TryParse() вместо int.Parse() позволяет избежать падения программы при вводе некорректных данных (например, текста вместо числа).

Каждая конструкция имеет своё назначение. if/else удобен для сложных условий, switch — для сравнения одной переменной с конкретными значениями, тернарный оператор — для выбора одного из двух значений в одну строку.

## Ответы на вопросы

### 1. Чем int.TryParse() безопаснее int.Parse()? В каких случаях стоит использовать каждый?

`int.Parse()` выбрасывает исключение `FormatException`, если строка не является числом, — программа падает.  
`int.TryParse()` возвращает `true`/`false` и не выбрасывает исключение — программа продолжает работу.

- `int.Parse()` — когда данные точно корректны (например, из проверенного файла).
- `int.TryParse()` — при вводе от пользователя, где возможны ошибки.

### 2. Когда switch удобнее, чем цепочка if/else if? Приведите пример из реальной жизни.

`switch` удобнее, когда одна переменная сравнивается с несколькими конкретными значениями. Код становится читаемее.

**Пример:** обработка нажатия кнопки пульта.

```csharp
switch (button)
{
    case 1: Console.WriteLine("Первый канал"); break;
    case 2: Console.WriteLine("Второй канал"); break;
    case 3: Console.WriteLine("Третий канал"); break;
    default: Console.WriteLine("Неизвестная кнопка"); break;
}
```
### 3. Что произойдёт в switch, если убрать break после одного из case?
Выполнение «провалится» в следующий `case`. В `C#` это разрешено только для пустых case, идущих подряд (группировка). В остальных случаях компилятор выдаст ошибку.
### 4. Чем отличается = от == в C#? Почему это частая ошибка?
`=` — присваивание, `==` — сравнение. Ошибка частая, потому что символы похожи.Можно случайно написать `if` `( = )` вместо `if` `( == )`. В `C#` это приведёт к ошибке компиляции.
